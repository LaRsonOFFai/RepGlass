# Пользовательский сценарий RepGlass 1.2

Оригинальный Glass использован как поведенческая спецификация, но его старый код и облачный
контур не перенесены. RepGlass сохраняет сильные сценарии и устраняет их ограничения.

| Сценарий | Оригинальный Glass | RepGlass 1.2 |
| --- | --- | --- |
| Активная сессия | Listen/Ask связаны через repository | Один контекст процесса до «Новая сессия» |
| Говорящие | Две STT-сессии `Me`/`Them` | Две Realtime STT-сессии «Вы»/«Собеседник» |
| Аудио | Устаревший ScriptProcessor и платформенные ветки | AudioWorklet, VAD и PCM16 24 kHz |
| Текстовый Ask | Вопрос, история и автоматический screenshot | Обычный Ask использует smart-screen; `Ctrl+Enter` всегда добавляет новый screenshot |
| `Ctrl+Enter` | Открытие Ask или screen-only | Текст → вопрос собеседника → screen-only fallback |
| Контекст | Ask обрезает историю последними 30 строками | Транскрипция, вопросы и ответы с начала запуска |
| Ответы | Отдельное Ask-окно и навигация | Панель Ask в единственном BrowserWindow, один активный запрос и история |
| Итоги | Инкрементальный summary каждые 5 реплик | Live Insights во время разговора и финальный Summary по «Завершить» |
| Снимок | Захват display без явного скрытия UI | Сериализованный захват со скрытием окна и tray |
| Хранение | SQLite/Firebase и web-панель | Только память активной сессии; ключ шифруется DPAPI |
| Авторизация | Набор API providers | Codex OAuth для ответов, Platform API key для STT |

## Умный запрос

`Ctrl+Enter` выполняет один предсказуемый сценарий:

1. Если пользователь ввёл текст, отправляется этот текст и новый снимок экрана.
2. Если поле пустое, используется последняя реплика собеседника и новый снимок.
3. Если транскрипции ещё нет, модель анализирует видимую задачу только по снимку.

Обычная кнопка отправки использует режим экрана из настроек: `Выкл.`, `Умный` или `Всегда`.

## Живое интервью

1. Кнопка «Слушать» открывает отдельные transcription WebSocket для микрофона и loopback.
2. Реплики пользователя пополняют контекст, но при двух источниках не запускают автоответ.
3. Завершённые вопросы собеседника проходят локальный детектор и очередь cooldown.
4. Вопросы про код, ошибку или задачу получают свежий приватный снимок.
5. При попадании звука колонок в микрофон совпадающая микрофонная транскрипция удаляется.
6. «Пауза» сохраняет контекст; «Завершить» формирует финальные итоги.

## Экран и Ask

Каждый запрос хранит собственные источники `Текст`, `Аудио`, `Экран`, триггер и превью.
Снимок показывается непосредственно над ответом, который его использовал, и не переносится на
последующие ответы. Пункты Live Insights и Summary можно нажать, чтобы открыть их в Ask.

Контекст не переживает полный перезапуск приложения и не записывается на диск. Это сознательный
компромисс между полезной памятью во время интервью и приватностью после его завершения.
